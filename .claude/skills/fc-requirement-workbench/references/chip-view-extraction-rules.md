# 芯片手册分阶段信息提取规则

本文档定义需求生成阶段如何将芯片手册全量信息按下游阶段视角拆分为两个结构化视图。每个视图只包含对应阶段真正需要的芯片信息，不做架构决策、不做代码常量编写。

## 1. 提取时机与触发条件

```
需求生成阶段
  ├── 检查输入中是否包含芯片手册
  │     ├── 否 → 跳过提取，后续阶段按 L2 输入等级运行（自行从全量手册提取或标记缺料）
  │     └── 是 → 检查 Output/<FC>/Doc/ChipViews/ 下是否存在 2 个提取文件
  │             ├── 全部存在 → 跳过提取
  │             └── 任意缺失 → 触发提取流程，补全缺失文件
  └── 提取完成后，继续正常需求生成流程
```

两个提取文件独立存在、独立生成，缺失哪个补哪个，不全量重跑。

## 2. 通用约束

- 两个视角只做芯片原始信息的结构化重组和呈现
- 不做任何代码常量的命名（不写 `#define`、不定义宏名、变量名）
- 不做 C 表达式编写
- 不做任何架构决策（分类、归并、取舍留给下游阶段自行决定）
- 芯片手册中无法获取的信息留空或标注"手册未说明"，不凭空补充
- 两个视角采用结构化 Markdown，固定表格 schema，确保下游 skill 可机读

## 3. 视角 1：`<FC>_芯片架构输入.md`

**服务阶段**：架构生成
**提取原则**：只回答"芯片提供了什么资源，资源长什么样"，不做分类、分组、归并等架构决策。

### 3.1 提取域定义

#### A1. 模块身份

| 字段 | 说明 | 芯片手册来源 |
|------|------|-------------|
| 芯片型号 | 完整型号 | 封面/文档标题 |
| 制造商 | 厂商名称 | 封面 |
| 数据手册版本 | 文档版本号/日期 | 文档信息页 |
| 功能一句话 | 中文，不超过50字 | Features/General Description |
| 通信接口类型 | SPI / I2C / 并行 / 纯 DIO | Interface/Communication 章节 |
| 通信接口最大速率 | MHz 或 kbps | Electrical Characteristics |
| 功能安全等级 | QM / ASIL-B / ASIL-D，手册未标注则记"未声明" | Safety/认证章节 |

#### A2. 引脚清单

每个引脚一行：

| 字段 | 说明 |
|------|------|
| 引脚名 | 芯片手册中的引脚名 |
| 方向(Mcu视角) | Input / Output / Bidir |
| 功能 | 一句话中文 |
| 有效电平 | High 有效 / Low 有效 / — |
| 内部上下拉 | 内部 Pull-up / Pull-down / 无 / 手册未说明 |
| 是否必须连接 | 必须 / 可选 / NC(可浮空) |

#### A3. 工作模式

| 字段 | 说明 |
|------|------|
| 模式名 | Normal / Sleep / Standby / Fault / ... |
| 进入方式 | 引脚触发 / SPI命令触发 / 芯片硬件自动 |
| 退出方式 | 引脚触发 / SPI命令触发 / 自动恢复 |
| 该模式下可用功能 | 列出哪些功能在该模式下可用 |
| 上电默认 | 标记是否为上电默认模式 |

#### A4. 寄存器空间概览

| 字段 | 说明 |
|------|------|
| 寄存器名 | 芯片手册中的寄存器名称 |
| 地址 | hex 地址 |
| 位宽 | 8 / 16 / 32 |
| 访问属性 | R / W / R/W |
| 功能分类 | 控制 / 状态 / 配置 / 数据 / 身份 |
| 一句话功能 | 中文，不超过30字 |

另附**寄存器分类统计表**：

| 功能分类 | 寄存器数量 | 寄存器列表 |
|----------|-----------|-----------|
| ... | ... | ... |

#### A5. SPI/I2C 帧协议

仅当芯片使用 SPI 或 I2C 接口时提取：

| 字段 | 说明 |
|------|------|
| 帧位宽 | 8bit / 16bit / 32bit |
| 命令结构 | R/W bit 位置、地址位宽、数据位宽 |
| 响应结构 | 状态字节位置、数据字节位置 |
| 地址空间范围 | 可寻址寄存器范围 |
| Burst Read | 支持 / 不支持，如支持注明最大长度和地址递增行为 |
| Burst Write | 支持 / 不支持 |
| CRC | 无 / 有(注明多项式和覆盖范围) |
| 帧间最小 CS 高电平 | 时间值 |

#### A6. 中断资源

| 字段 | 说明 |
|------|------|
| 中断源名 | 中断源名称 |
| 触发条件 | 什么条件触发该中断 |
| 标志位 | 所在寄存器.bit |
| 清除机制 | 读清零 / 写1清零 / 自动清零 |
| 是否可屏蔽 | 是 / 否 |

#### A7. 时钟与复位

| 字段 | 说明 |
|------|------|
| 时钟源 | 内部 OSC / 外部晶振 / 总线时钟 |
| 复位源列表 | POR / nRESET 引脚 / 软件命令 / 看门狗 |
| 各复位源影响范围 | 全量复位 / 部分复位(注明影响哪些寄存器) |
| 复位后默认模式 | 芯片复位后进入的模式 |
| 复位恢复时间 | 复位释放到可接受通信命令的时间 |

### 3.2 视角 1 明确不包含

- bit 段定义
- 时序数值
- 故障行为
- 状态转换条件
- 初始化序列
- 精确 hex 掩码/移位量
- 命令字节编码
- 读写副作用
- 访问约束规则
- 数据组装规则

## 4. 视角 2：`<FC>_芯片详细设计输入.md`

**服务阶段**：详细设计生成 + 代码生成
**提取原则**：在视角 1 基础上追加行为级信息和精确数值常量。每个寄存器条目同时包含行为语义和精确常量，使详细设计阶段能在一个文档中完成行为设计决策和常量定义，无需在两张表之间跳转。

### 4.1 提取域定义（视角 1 基础上追加）

#### D1. 寄存器完整行为与常量表

将原视角 2 的位段行为（D1）与原视角 3 的精确数值（C1）、读副作用（C2）、访问约束（C3）合并为每个寄存器的统一条目。逐寄存器展开，每个 bit 一行：

| 字段 | 说明 | 来源域 |
|------|------|--------|
| bit | bit 位置，如 `7`、`6:5` | D1 |
| 位段名 | 芯片手册中的 bit 段名称 | D1 |
| 位段掩码(hex) | 如 `0x80` | C1 |
| 移位量 | 如 `7` | C1 |
| 访问属性 | R / W / R/W | D1 |
| 复位值(hex) | 如 `0xFF` | D1 + C1 |
| 功能语义 | 该位段的功能含义 | D1 |
| 枚举值 | 如 `0=输出, 1=输入` | C1 |
| 行为约束 | 读清零 / 写1清零 / 仅 X 模式下可写 / 保留位必须写0 / ... | D1 |

对每个寄存器单独列出，不合并。纯 Reserved 寄存器可只记地址和名称。

每个寄存器后附**寄存器级约束摘要**（合并 C2 + C3）：

| 寄存器(地址) | 读副作用 | RMW是否必须 | 保留位写策略 | 写后等待时间 | 模式访问限制 |
|-------------|---------|------------|------------|------------|------------|
| REG (0xXX) | 无副作用 / 读清零 / ... | 是 / 否 + 原因 | 忽略 / 必须写0 / 保留原值 | 数值(us) | 说明 |

#### D2. 状态转换条件

| 字段 | 说明 |
|------|------|
| 当前状态 | 状态名 |
| 下一状态 | 状态名 |
| 触发条件 | 硬件事件 / 软件命令 / 自动 |
| 判定方式 | 轮询寄存器 bit / 中断触发 / 引脚电平 |
| 转换延迟 | 从触发到转换完成的典型时间 |

#### D3. 故障源行为

| 字段 | 说明 |
|------|------|
| 故障名 | 故障名称 |
| 故障类型 | 芯片故障 / 驱动逻辑故障 |
| 硬件触发条件 | 芯片在什么硬件条件下判定为故障 |
| 可观测标志位 | 哪个寄存器的哪个 bit 指示该故障 |
| 芯片硬件自动响应动作 | 故障发生时芯片自动执行的动作（如禁用输出、拉低 nFAULT） |
| 清除方式 | 写1清零 / 读清零 / 需要重新上电 / ... |
| 清除前置条件 | 清除前需要满足什么条件（如故障条件已解除） |
| 是否自恢复 | 是 / 否，若是则注明恢复条件 |

#### D4. 操作时序参数

| 字段 | 说明 |
|------|------|
| 参数符号 | 芯片手册中的符号（如 T_POR） |
| 含义 | 中文 |
| 典型值 | 数值 |
| 最小值 | 数值 |
| 最大值 | 数值 |
| 单位 | ms / us / ns |
| 用途场景 | 该时序参数在设计中的用途 |

#### D5. 初始化约束

芯片手册规定的初始化操作顺序与依赖，合并精确常量：

| 字段 | 说明 |
|------|------|
| 序号 | 步骤编号 |
| 操作 | 步骤内容描述 |
| 前置条件 | 该步骤的前置依赖 |
| 判定成功标准 | 如何判定该步骤成功 |
| 精确等待时间 | 如 `>= 200ns`（来自 C7） |
| 期望读回值(hex) | 如 `0xFF`（来自 C7） |
| 失败重试次数上限 | 数值（来自 C7） |
| 失败行为 | 该步骤失败时的处理方式 |

#### D6. 读回数据组装规则

（原视角 3 C4，从纯代码视角迁入）当芯片中一个逻辑值跨越多个寄存器时：

| 字段 | 说明 |
|------|------|
| 逻辑值名称 | 如"16位输入值" |
| 源寄存器 | 各寄存器名+地址 |
| 各寄存器取值 bit 段 | 如"IP0[7:0]=P00~P07, IP1[7:0]=P10~P17" |
| 组装后总位宽 | 12bit / 16bit / ... |
| 有无符号 | 无符号 / 有符号 |
| 符号位位置 | 如 bit11 |
| 组装顺序约束 | 如"必须先读高字节再读低字节(读高字节时锁存低字节)" |

#### D7. 命令/响应编码

（原视角 3 C5）当芯片使用 I2C/SPI 等总线时：

器件地址表：

| A1 | A0 | 7位地址(hex) | 写地址(hex) | 读地址(hex) |
|----|----|-------------|-----------|-----------|
| L | L | ... | ... | ... |

命令字节表：

| 命令字节(hex) | bit 段 | 目标寄存器 | 操作 |
|--------------|--------|-----------|------|
| ... | ... | ... | 读 / 读/写 |

读写帧序列表（分写操作和读操作两张表，每步列出内容、方向、说明）。

#### D8. 跨寄存器关系

（原视角 3 C6）

| 字段 | 说明 |
|------|------|
| 约束项 | 描述，如"Burst读写时寄存器在port 0↔port 1间交替" |
| 更新顺序要求 | 如"应先写Configuration再写Output" |
| Burst 地址递增边界 | 如"寄存器对内交替(0x00↔0x01)，无地址回绕" |

### 4.2 视角 2 明确不包含

- `#define` 宏名
- C 变量名
- C 表达式
- 代码片段
- 架构决策（分类、归并、取舍留给架构阶段自行决定）

只给原始行为语义、精确数值和约束规则，命名和写法由下游阶段自行决定。

## 5. 两视角的递进关系

```
视角 1 (架构)       →  视角 2 (详细设计 + 代码)
═══════════════════════════════════════════════════
寄存器名+分类       →  + bit 段语义 + hex 掩码+移位量 + 枚举值 + 读副作用 + RMW/保留位/写后等待
模式名+进入方式     →  + 转换条件+延迟
故障标识位         →  + 触发条件+清除方式+自恢复标记
时序参数名         →  + 完整最小/典型/最大值+用途
初始化步骤序       →  + 前置条件+判定+精确等待时间+期望读回值+重试参数
                      数据组装规则
                      命令 hex 编码
                      跨寄存器关系
```

视角 2 的信息增量覆盖了原视角 2（行为语义）和原视角 3（精确常量）的全部内容，使详细设计阶段一次性获取完整信息。

## 6. 输出路径与文件命名

```
Output/<FC>/Doc/ChipViews/
├── <FC>_芯片架构输入.md          # 视角 1：架构生成
└── <FC>_芯片详细设计输入.md       # 视角 2：详细设计 + 代码生成
```

- 两个文件独立存在、独立生成，缺失时单独补全
- `<FC>` 与同模块 SRS/SDD/SDS 产物保持一致的模块短名
- 格式统一为结构化 Markdown，固定表格 schema
