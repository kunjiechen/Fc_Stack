# Gate 6 SDS 输入充分性检查清单

## 1 检查目标

确认 SDD 已为软件详细设计（SDS）、编码实现和 IT/ST 验证提供足够、明确、可追溯的输入，避免 SDS 或 Coding 阶段自行补充未定义的软件行为。

## 2 适用阶段

SDD 技术检查完成后、进入 SDS 阶段前。

## 4 下游不可接受情形

存在以下情形时，不建议进入 SDS：

- API 名称、参数、返回值或错误行为未固定。
- 状态集合或状态转移不完整。
- 配置项范围、结构或失效行为不明确。
- Callout 和下层依赖边界不明确。
- 安全机制或诊断边界缺失。
- 多核/重入共享数据无保护策略。
- SDS 需要自行决定关键架构行为。
- 高影响开放项未关闭且未获批准。

## 5 不通过处理

| 问题类型 | 处理要求 |
| --- | --- |
| SDS 输入缺失 | 回到 SDD 补充设计或回写 SRS 输入缺口 |
| 接口未固定 | 补充 InterfaceSpec 或 SDD 接口章节 |
| 状态未固定 | 补充 StateMachine 或 SDD 状态机章节 |
| 配置未固定 | 补充配置结构、范围和校验规则 |
| 安全/诊断未固定 | 补充 SafetyDesign、诊断边界和验证入口 |
| Open 项阻塞 SDS | 关闭 Open 项或评审批准遗留风险 |
