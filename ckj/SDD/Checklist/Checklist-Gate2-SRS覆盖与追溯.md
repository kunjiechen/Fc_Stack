## 1 检查目标

确认每条有效 SRS 需求均已被 SDD 架构设计覆盖、明确 N/A 理由或登记开放项，确保 SRS 到 SDD 的前向和后向追溯完整。

## 2 适用阶段

SDD 初稿完成后、架构评审前。

## 4 下游不可接受情形

存在以下情形时，不建议进入 SDD 评审：

- 有效 SRS 未出现在追溯矩阵中。
- SRS 被标记 N/A 但无理由。
- 安全相关 SRS 未追溯到安全机制或验证策略。
- SDD 设计项无法追溯到任何 SRS、标准、系统约束或批准决策。
- 未覆盖项影响 SDS 编写但未登记开放项。

## 5 不通过处理

| 问题类型 | 处理要求 |
| --- | --- |
| SRS 未覆盖 | 补充 SDD 设计、说明 N/A 或登记开放项 |
| SDD 无来源 | 删除设计项、补充来源或形成架构决策记录 |
| 追溯粒度过粗 | 拆分 SDD 项或补充设计入口 |
| 安全追溯缺失 | 补充 SafetyDesign 或回写安全输入缺口 |
| Open 项未管理 | 增加责任人、影响分析和关闭条件 |
