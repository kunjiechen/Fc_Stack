# Gate 4 架构技术正确性检查清单

## 1 检查目标

确认 SDD 架构设计在技术上正确、可实施、无明显架构冲突，并满足接口、数据、状态、诊断、安全、多核、资源和集成约束。

## 2 适用阶段

SDD 内容完整性检查通过后、架构评审结论形成前。

## 4 下游不可接受情形

存在以下情形时，不建议进入 SDD 基线：

- 接口参数或返回值语义不清。
- 状态机存在未定义转移或状态语义混淆。
- 错误处理只有返回失败，无失败后置条件。
- 安全机制无来源或无响应动作。
- 多核共享数据无保护策略。
- 依赖方向形成循环或上层穿透访问下层内部实现。
- SDS 仍需自行假设关键行为才能继续设计。

## 5 不通过处理

| 问题类型 | 处理要求 |
| --- | --- |
| 技术设计不成立 | 修改架构设计或回写 SRS 输入缺口 |
| 接口不清 | 补充 API 属性、返回值、错误处理和前后置条件 |
| 状态不清 | 补充状态语义、转移表和异常路径 |
| 安全不清 | 补充安全来源、故障响应、降级和验证入口 |
| 多核/重入不清 | 补充共享资源、同步策略和调用约束 |
| 资源时序不清 | 补充估算、测量计划或约束边界 |
