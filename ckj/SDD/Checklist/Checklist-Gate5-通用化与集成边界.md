# Gate 5 通用化与集成边界检查清单

## 1 检查目标

确认 SDD 将 FC 通用架构、配置裁剪能力、Callout/依赖适配和项目集成约束清晰分离，避免把单一项目或单一板级环境的实现细节固化为 FC 固有架构。

## 2 适用阶段

架构技术正确性检查后、SDD 基线发布前。

## 4 常见不通过情形

- 把当前项目任务名、函数调用链或调度配置写成 FC 固有架构。
- 把当前板级引脚、极性、通道号写死在 FC 通用接口语义中。
- 把芯片手册中存在但 SRS 未要求的能力写成 FC 必须支持能力。
- 把当前配置未启用能力描述成运行时已生效能力。
- Callout 名称和语义直接暴露供应商 MCAL 或板级细节。
- 未说明更换 MCU、板级、OS 或项目时哪些设计保持不变、哪些需要适配。

## 5 不通过处理

| 问题类型 | 处理要求 |
| --- | --- |
| 项目化固化 | 改写为配置项、Callout、依赖抽象或集成约束 |
| 芯片能力误写 | 移至支持/非支持能力表，补充处理方式 |
| 当前配置误写 | 区分源码具备、配置可启用和当前启用状态 |
| 板级细节泄露 | 下沉到 Callout 或配置，不污染公共 API 语义 |
| 集成示例混淆 | 明确标注为示例或项目集成约束 |
