# Gate 5 通用化与适配边界检查清单

## 1 检查目标

确认 SDS 保持 FC 的通用化主体设计，正确隔离项目差异、平台差异和硬件差异，避免将一次性集成方案固化为通用详细设计。

## 2 适用阶段

SDS 技术正确性检查后、进入 Coding 输入充分性检查前。

## 3 通用化与适配检查

| 序号 | 检查对象 | 检查项 | 通过标准 | 结果 | 问题记录 |
| --- | --- | --- | --- | --- | --- |
| G5-01 | 主体逻辑 | 是否保持 FC 主体逻辑通用化 | 核心处理步骤不依赖单一项目临时假设 | [ ] Pass [ ] Fail [ ] N/A | |
| G5-02 | 配置裁剪 | 差异是否优先通过配置承载 | 能力开关、实例数、通道映射等差异通过配置表达 | [ ] Pass [ ] Fail [ ] N/A | |
| G5-03 | Callout 适配 | 硬件/平台差异是否通过 Callout 承载 | 差异性依赖未散落在主体函数分支中 | [ ] Pass [ ] Fail [ ] N/A | |
| G5-04 | 集成前提 | 集成前提是否明确分离 | OS、调度、硬件稳定时间、上层时序等作为前提条件描述 | [ ] Pass [ ] Fail [ ] N/A | |

## 4 不通过处理

| 问题类型 | 处理要求 |
| --- | --- |
| 项目化逻辑固化 | 提炼为配置、Callout 或集成前提 |
| 主体与适配边界混杂 | 重整文件和函数职责边界 |
| 条件编译掩盖未设计行为 | 补充主体设计或删除模糊开关 |
| 迁移边界不清 | 明确保持不变部分和适配变化部分 |
