## 2. 评审重点

### 2.1 结构完整性

- 15 个章节全部覆盖，符合 `output-template.md` 正式模板要求
- 外部接口 7 个、内部函数 8 个、Callout 6 个，每个均按 full-per-function 规则全面展开（prototype 表 + 子功能分解 + 执行步骤 + 调用关系表 + 流程图）
- 配置参数双维度（宏参 12 个 + 配置类型 4 个）、运行参数双维度（变量 12 个 + 运行参数类型 4 个）
- 状态机、DET、故障处理、MemMap 各章完整

### 2.2 规则合规性

| 规则域 | 检查项 | 结论 |
| --- | --- | --- |
| 单核纯度 | 所有流程图中无 core-matching、CalloutGetCoreId、per-core-index 节点 | 通过 |
| MainFunction | 判定不需要，理由明确（纯同步事件驱动，无周期采样/状态机推进需求） | 通过 |
| Cfg.c | 存在配置表实例化（per-instance 配置表），已创建 | 通过 |
| Internal.h | 无需跨文件内部复用，未创建，理由充分 | 通过 |
| Reg.h | FC 控制 I2C 寄存器外设，已创建 | 通过 |
| Callout | 硬件变化隔离 + 延时需求，已创建 Callout.h/.c | 通过 |
| NoClear | 无 reset continuity 需求，未使用 | 通过 |
| DET vs Fault | 严格区分：DET 6 个检查点（API 滥用），Fault 3 个故障项（运行时异常） | 通过 |
| 设计增量溯源 | 6 个新增宏参均标记 `design-addition (Rx)`，对应风险项 R1-R8 | 通过 |

### 2.3 芯片数据 (D1-D8) 消费完整性

| D域 | 消费到的章节 | 消费方式 | 校验 |
| --- | --- | --- | --- |
| D1 寄存器行为 | §6.1 执行步骤、§6.2 内部函数、§11 配置常量、§10 运行参数 | 读副作用（读 Input Port 清除 INT\）→ 中断处理步骤；RMW 约束 → 无 RMW（D1 确认所有 R/W 寄存器无保留位） | 通过 |
| D2 状态转换 | §7 状态机 | 完整映射：POR/Reset→正常运行、正常运行→复位、正常运行→待机 | 通过 |
| D3 故障源 | §9 Fault | 中断事件重分类为通知机制，POR/欠压复位通过 I2C NACK 和寄存器默认值异常间接覆盖 | 通过 |
| D4 时序参数 | §11 配置宏参、§6.1 执行步骤、§6.3 Callout 约束 | t_rec(rst) → CalloutDelayUs、t_v(Q) → FC_CFG_T_V_Q_MAX_NS、t_w(rst) → FC_CFG_T_W_RST_MIN_NS | 通过 |

| D7 命令编码 | §6.3 Callout 行为约束、§11 配置常量 | 器件地址表 (0x74~0x77)、命令字节 (0x00~0x07)、I2C 读写帧序列 | 通过 |
| D8 跨寄存器关系 | §6.1 执行步骤顺序约束、§6.2 内部函数 | Burst 交替行为、输出生效依赖方向配置 | 通过 |
