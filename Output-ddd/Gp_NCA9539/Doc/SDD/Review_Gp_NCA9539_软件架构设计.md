## 1. 评审重点

以下为本次架构评审需重点关注的方面：

### 1.1 接口完整性

- 7 个外部接口是否覆盖了所有 SRS 接口需求（INTF-0001 ~ INTF-0006）
- `GetFaultStatus` 诊断接口是否满足 DIAG-0002 的故障信息查询粒度
- `Deinit` / `Reinit` 接口的缺失是否需要补充（见 R8）

### 1.2 依赖接口合理性

- 5 个 Callout 的边界划分是否清晰：I2C 读写由 Callout 封装、RESET/INT 引脚由 DIO Callout 控制
- `CalloutGetCoreId` 在多核未确认时是否为过度设计
- Callout 原型是否符合项目接口规范（指针形参、`uint16 Size_u16`、无数组声明式）

### 1.3 MainFunction 判定

- 架构判定 MainFunction 不需要的理由是否充分：无周期采样/状态机推进/去抖/看门狗/缓冲请求处理
- 若 SAFE-0002 运行期间回读需要周期执行，本判定需修正（见 R4）

### 1.4 MemMap 段完整性

- 7 个 MemMap 段是否遗漏必要类别
- per-core vs global 的划分是否符合项目多核策略（见 R9）
- REG CONST 段是否独立列出（I2C 寄存器外设必须独立）
- CODE RAM COPY 的条件是否存在真实需求（见 R3）

### 1.5 配置宏参最小化

- 6 个配置宏参是否均为必要，是否遗漏关键编译期决策
- 是否存在"为每个外部接口生成一个宏"的过度配置

### 1.6 标定项判定

- IoExtDev 族标定项为空的判定是否合理
